### 方案 1：獨立新網頁，前端直連 MQTT

- **優點：**
    - **零耦合：** 完全不影響現有的客戶端 API 與既有 Web App，確保現行系統穩定。
    - **開發時程短：** 可直接複用現有「智慧電表」的頁面組件與訂閱邏輯，修改成本低。
    - **專案維護獨立：** 採用獨立專案資料夾管理，技術債不與舊系統交織。
    - **輕量化部署：** 導入 PWA技術，即可提供類原生 App 的外觀與操作體驗，免去額外開發行動端 App 的成本。
- **缺點：**
    - **功能受限：** 前端直連 Broker，未與後端資料庫通訊，**無法提供歷史數據查詢與報表功能**。
    - **資安防護與展示的衝突：** 若考量控制安全性，本方案建議部署於內部伺服器（如內網 VPS 3），這將導致**無法直接在外網向客戶展示**；若放開至外網，前端直連 MQTT 容易暴露 Topic 命名規則與連線憑據，具備資安風險。

### 方案 2：沿用舊架構，擴充權限分級 API 與 Web APP

- **優點：**
    - **資源複用：** 融入既有架構，直接在現有基礎上進行疊加與優化。
    - **一體化體驗：** 同一套前端頁面，根據使用者角色（Role-based）動態切換權限，實現差異化操作。
    - **現成基礎設施：** 現行外網通訊與 HTTPS 安全加密架構已完備，可直接在外網進行跨場域查看。
    - **資料完整：** 後端架構健全，可直接調取並展示完整的歷史趨勢數據。
- **缺點：**
    - **資安與信任風險：** 營運端控制功能與一般客戶端頁面混在同一個專案，難免引發客戶對控制權限隔離性的疑慮。
    - **回歸測試成本高：** 由於新舊邏輯交織，開發與測試週期較長，且容易牽一髮而動全身。
    - **客戶端更新異步風險：** 若要隱藏特定控制頁面，必須大幅變動 Web APP；但在使用者未強制更新 App 的過渡期內，舊版 App 依然可用，可能造成安全控制漏洞。
    - **維護負擔遞增：** 單一 Web APP 承載過多業務邏輯，未來系統維護與功能驗收的複雜度將大幅提升。

### 方案 3：解耦新架構，建置新 Web 運維端並擴充身分識別 API

- **優點：**
    - **特化 UI 設計：** 前端版面全新重構，能針對「全機櫃狀態（BMS/EMS）」進行客製化的大螢幕或高密度看板規劃。
    - **零侵入性：** 完全不需要改動現行的客戶端 Web APP，將營運風險降至最低。
    - **核心業務隔離：** 兩端（客戶端與運維端）功能徹底解耦，互不干擾，資安邊界清晰。
    - **跨平台體驗：** 同樣支援 PWA 技術，可快速打包成桌面/行動端快顯軟體，無需負擔 App 開發成本。
    - **利於未來維護：** 新建獨立專案，程式碼乾淨，方便未來功能迭代與模組化管理。
- **缺點：**
    - **初期投入高：** 涉及全新前端建置與後端 API 擴充，開發與整體整合測試的時程較長。
    - **鑑權機制成本：** 如需要對外，後端需額外設計、修改 API，建立額外認證機制。
