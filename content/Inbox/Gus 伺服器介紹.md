# Computex 展場實戰應對指南：講能力，不講實作

> **核心戰略：** 展場是「篩選器」，不是技術發表會。
> 面對一般人展現 **UI 與整合速度**；面對技術型客戶展示 **現場經驗與痛點解決能力**。核心控制策略與底層架構一律留下資料後再翻牌。

---

## 戰線一：家用儲能 (Residential ESS)
**【主打優勢】** 一體化整合、極速部署、高互動性、智慧邊緣。
**【目標客群】** 品牌商、經銷商、安裝商、海外買家。

### 1. 整合式系統與全平台 (App / Web) 設定
* **對方怎麼問：** 「你們系統可以控制 PCS 嗎？還是只能看數據？」
* **實戰話術 ：** 
  > 「我們的系統實現了真正的 **All-in-One 整合**。使用者或安裝商不需要去開傳統難懂的 PCS 後台，我們直接把 PCS 設定、充放電排程與電池狀態（SoC/SoH），全部整合進同一個手機 App 與網頁端。從現場配網到日常看 Power Flow 動畫，一隻手機、電腦就能全部搞定。」
* **潛台詞：** 我們的 UI/UX 極佳，能幫安裝商省下大量的現場調試（Commissioning）時間。

### 2. 快配通訊驅動與 Point List 快速動態上線
* **對方怎麼問：** 「如果我們想搭我們自己品牌的 PCS 或不同廠牌的電池，你們要改多久？」
* **實戰話術 ：** 
  > 「這正是我們的核心強項。我們底層開發了標準化的**通訊驅動模組**，擁有非常豐富的現場 Mapping 經驗。只要貴司把設備的 **Point List（暫存器對照表）**提供出來，我們幾天內就能完成設定並動態上線，不需要重新寫程式。不論你們想搭哪一家的硬體，我們都能當最強的軟體後盾。」
* **潛台詞：** 我們軟體彈性極高、相容性強，你們換硬體供應商也不用怕。

### 3. 斷網防護與本地策略執行
* **對方怎麼問：** 「如果家裡 Wi-Fi 斷線、或是雲端斷了，系統會不會停擺？」
* **實戰話術 ：** 
  > 「完全不會。我們的架構具備邊緣端的**自主執行與斷網續傳能力**。即使現場完全斷網，邊緣端依然會嚴格根據先前的設定值，繼續執行削峰填谷或備用電源策略。同時，所有的電費與運行數據都會完整保留在本地，等網路恢復後自動同步回雲端，絕不漏失任何一筆數據。」
* **潛台詞：** 系統穩定度是工控等級，不會因為家用網路不穩就變磚頭。

### 4. 閉環控制能力與進階 EMS 策略
* **對方怎麼問：** 「你們能做動態調頻或是防逆流控制嗎？」
* **實戰話術 ：** 
  > 「可以，我們系統具備**閉環控制（Closed-loop control）的能力**，能即時根據負載變動下令給 PCS，完美對接調頻、削峰填谷等 EMS 策略。不過這部分通常會牽涉到案場的 PCS 反應速度（Response Time）與硬體特性。有興趣的話可以留個資料，後續可以進行對接」
* **目的（拋誘餌）：** 用「閉環控制」證明實力，再用「PCS 反應速度」當誘餌，把真心想合作的客戶帶進下一步。

## 戰線二：高壓/工商儲能 (C&I / Utility ESS)
**【主打優勢】** 極致資安、高可靠度、大數據點數優化、懂電池底層。
**【目標客群】** SI 系統整合商、EPC 統包商、工廠自動化商、能源顧問。

### 1. Local 端（本地部署）與極致資安保密性
* **對方怎麼問：** 「我們是工廠/高科技大廠，數據不能上雲端，你們怎麼解？」
* **實戰話術 ：** 
  > 「沒問題，我們非常理解工業案場對資安的變態要求。除了雲端架構，我們特別開發了 **純 Local 端（地端）的監控運維方案**。所有的電網數據、高壓設備狀態、廠區商業機密，全部鎖在現場內部的伺服器，完全不對外網公開。這不僅符合高規格的資訊安全法規，更能確保貴司的數據自主權與絕對的保密性。」
* **潛台詞：** 我們不是只會玩雲端陽春系統的團隊，我們懂半導體大廠或高壓案場的資安痛點。

### 2. 多機並聯 (Multi-cluster) 與邊緣輪詢優化
* **對方怎麼問：** 「如果我們現場並聯了幾十個電池櫃，你們系統撐得住嗎？」
* **實戰話術 ：** 
  > 「高壓案場最怕通訊 Timeout。當多機並聯、數據點數動輒幾萬點時，一般系統畫面一定會卡頓。我們系統在 Edge Gateway 的**輪詢策略（Polling Strategy）**上做過深度優化。不論現場是多個電池櫃並聯還是多台電表，我們都能做到秒級的即時資料更新與同步控制，確保控制指令不延遲。」
* **潛台詞：** 我們是真的踩過現場並聯通訊坑的團隊，跟那些只會畫炫麗 UI 的攤位不一樣。

### 3. 三層架構 (MBU / BMU / BCU) 深度解析與告警
* **對方怎麼問：** 「你們對電池數據的掌握度到哪裡？」
* **實戰話術 ：** 
  > 「我們對電池底層非常熟悉。系統能完美對接高壓電池系統的 **三層架構（從最底層的 Cell/BMU、中階的 BCU，到最上層的 MBU）**。我們不只抓總電壓，我們還能做到單體電壓壓差告警與精準的故障定位，在電池發生熱失控或異常前，提早發出預警通知運維人員。」
* **潛台詞：** 我們懂電池化學與軟體結構，是真懂儲能的專業團隊。

## 防禦話術：遇到同業/抄襲型客戶問太細時

當對方一直追問：*「你們後端是用什麼寫的？」、「Local DB 是用 SQLite 還是 InfluxDB？」、「控制演算法的 Logic 怎麼寫？」*

* **防禦反擊話術 ：**
  > 「啊，這部分因為牽涉到我們團隊的核心專利與底層封裝架構，在展場現場比較不方便透露這麼細。不過主要就是為了確保在大點數下的控制效能。如果剛好有具體的案場正在尋找解決方案，我們可以互留個聯絡方式，請我們技術架構工程師對接。」
* **核心原則：** 軟釘子碰回去。
